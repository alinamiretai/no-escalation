# No-Escalation for Capability-Bearing Agent Systems: Property Statement

**Status:** working note, **v0.2** — integrates the verdicts of `benchmark-attacks-v0.1-verdicts.md`. Definitions are candidates until the Alloy checks (§11) pass.
**Purpose:** fix the formal property this project proves, before committing the calculus and mechanization.

## 1. Scope and threat model

Systems of *components* (agents, sub-agents, tool servers, caretakers) hold capabilities, invoke tools, exchange requests, and spawn sub-components over long trajectories. Components are partitioned into **untrusted** (adversarial: arbitrary strategies, including collusion across many steps, but no capability forging) and **trusted** (assumed to satisfy explicit contract obligations, §7; each obligation is a per-component lemma in the mechanization, so "trusted" means *carries a proof obligation*, not *assumed safe*).

The property concerns **effect escalation only**: causing effects beyond conferred authority. Information-flow escalation (covert channels, signalling through permitted effects) is out of scope (§9).

## 2. Effects, traces, contexts

- Fix a set **E** of atomic observable effects: tool invocations *with arguments*, spawns, sends. Argument-level granularity is required or attenuation is inexpressible. (**Q1, open:** finite E for the Alloy phase; structured E — pairs (op, arg) over possibly-infinite arg domains — permitted from the start in the Lean development.)
- Behavior is generated by a labeled transition system over *configurations* (all component states + in-flight messages). A **trace** is the induced sequence of effect occurrences.
- **Contexts.** Each component's execution state records the **provenance context** π of the request it is currently processing: a sequence ⟨(C₀, β₀), (C₁, β₁), …⟩ of (component, attached bound) pairs, extended at each hop. A component acting on its own initiative has the empty context ⟨⟩. Every effect occurrence ε in a trace carries the context π(ε) under which it was performed, and its performer perf(ε).

Contexts in the execution state are the operational content of "chain attribution." This is the central bookkeeping commitment of the calculus.

## 3. Capabilities, stores, direct authority

- A **capability** c is an unforgeable reference with **fixed** denotation ⟦c⟧ ⊆ E. Attenuation: c′ with ⟦c′⟧ ⊆ ⟦c⟧. (Fixed denotations survive revocation via §6's caretaker-as-component move.)
- Each component C has a store σ(C). **Direct authority:** DA(C) = ⋃ { ⟦c⟧ : c ∈ σ(C) } (Miller's *permission*; Bishop–Snyder de jure).
- **Ocap discipline (assumption A2).** No ambient/global store. A freshly spawned component's store is exactly what its spawner passed. Untrusted components acquire capabilities only by receiving them.

## 4. Attribution and bounds

- **Component bounds.** Each C carries B(C) ⊆ E in the state, with **monotonicity (A4)**: every transition satisfies B′(C) ⊆ B(C).
- **Attached bounds.** Every send/delegation carries a bound β ⊆ E chosen by the sender. No side condition is imposed on β (a wider β is harmless — see effective bound below); this keeps the calculus small.
- **Attribution (the single relation).** attributed(ε) = { perf(ε) } ∪ { C : (C, ·) ∈ π(ε) }. Used uniformly by NE, EA, and every theorem. Performer-only attribution is refuted by Benchmark 1.
- **Effective bound of an occurrence.** effbound(ε) = B(perf(ε)) ∩ ⋂ { β : (·, β) ∈ π(ε) }. For empty context this is just B(perf(ε)).

## 5. The property

- **NE (no-escalation, unified).** On every trace, every effect occurrence ε satisfies ε ∈ effbound(ε).
  - Projection **NE-T** (component view): ε ∈ B(perf(ε)) — every component stays within its own bound.
  - Projection **NE-D** (delegation view): ε ∈ ⋂ β over π(ε) — every deputized effect stays within what the request chain conferred.
  - NE is prefix-closed and finitely refutable: a violation is a finite trace ending in one out-of-bound occurrence. It is a property of individual traces — a safety property in the Alpern–Schneider sense, not a hyperproperty — so McCullough-style non-composability of noninterference does not apply. (Claim to be re-verified against McCullough 1987/88 and Clarkson–Schneider 2010 before freezing.)
- **EA (eventual authority).** EA(C) = { e : some reachable continuation contains an occurrence ε of e with C ∈ attributed(ε) }. The DA/EA gap is the confused deputy's habitat; both are kept as first-class objects.
- **NE-S (inductive invariant, sketch).** In every reachable configuration: (i) for every component C, the effects reachably attributable to C via empty-context action lie within B(C); (ii) for every in-flight or in-service request context π, the effects reachably performable under π lie within ⋂β(π) ∩ B(current holder). NE-S is a configuration predicate quantifying over futures — not a trace property — and is the thing proved by rely–guarantee.
- **Lemma chain:** NE-S at all reachable configurations ⇒ NE on all traces. (Should be immediate from the definitions; if not, the definitions are wrong.)

## 6. Attenuation and revocation: the two axes of conferral scoping

Conferred authority is scoped on two axes, and the project's two original problems are exactly these axes:

- **Spatial scoping — attenuation + attached bounds.** *Which* effects are conferred: attenuated capabilities (⟦c′⟧ ⊆ ⟦c⟧) passed in requests, and attached bounds β narrowing the chain's effective bound. A component-level attenuation step is a transition strictly narrowing B(C).
- **Temporal scoping — revocation.** *For how long* conferral lasts. Mechanism: delegated capabilities are routed through a **caretaker** R (a trusted component, §7): the grantee holds c_R with fixed denotation ⟦c_R⟧ = { invoke(R, ·) }; R forwards invocations to the underlying c while uncleared. Authority over the underlying resource reaches the grantee only through EA, via R — DA stays simple and denotations stay fixed.
- **Revocation-effectiveness (target theorem).** If R is cleared at step k, then no occurrence of any e ∈ ⟦c⟧ attributable to the grantee is *issued* after k — provided the **alias-freedom invariant** holds: *direct references to revocable resources occur only in caretaker stores.* The proviso is structural (a reference-graph well-formedness invariant preserved by all transitions), not a runtime check; the runtime-check alternative is refuted by Benchmark 3 (cached direct reference never visits the check).
- **Weak revocation (linearization choice).** Invocations issued through R before the clear may complete; no invocations issued after the clear succeed. Chosen over strong (kill in-flight) as realistic for agent trajectories; the effectiveness theorem quantifies over post-clear *issuance* accordingly.
- **Retention is not escalation.** An untrusted component that retains a passed (attenuated) capability and uses it later under empty context acts within conferred spatial scope; if the grantor's intent was temporally bounded, the correct mechanism is caretaker routing, not a stronger spatial property. This resolves Benchmark 4 (laundering/retention) for untrusted components and motivates treating both axes in one framework.

## 7. The trusted-component class and its contracts

Two component roles carry obligations; these obligations are the rely–guarantee interfaces of the composition theorem, and each is a per-component lemma in the mechanization.

- **Guarding deputies** (components with ambient authority — e.g., a tool server holding its own credentials, which is an ambient c_T and unavoidable in the target domain):
  - **Guard:** perform an effect e using ambient authority under context π only if e ∈ effbound under π.
  - **Honest tagging:** effects caused by processing a request are performed under that request's context (no laundering into ⟨⟩). Making this an explicit obligation is what closes Benchmark 4 for trusted components: a "trusted deputy that launders" is by definition one that has violated its contract, and the theorem is stated conditionally on contracts.
- **Caretakers:**
  - **Membrane:** never emit the underlying reference — in any forward, return value, or spawn (Redell's caretaker / Miller's membrane as forwarding proxy, never handoff).
  - **Weak-revocation forwarding:** forward invocations iff uncleared, per §6's linearization.

Untrusted components carry no obligations; they are confined structurally by A1/A2 plus the property.

## 8. Assumptions and the target theorem

- **A1.** Capabilities are unforgeable; references cannot be guessed or minted.
- **A2.** Ocap discipline: no ambient store; spawn passes an explicit store (§3).
- **A3.** Trusted components satisfy their contracts (§7): Guard + Honest tagging; Membrane + Weak-revocation forwarding.
- **A4.** Bound monotonicity: B(C) never widens along any transition.

**Target theorem (composition).** Under A1–A4, every reachable configuration satisfies NE-S; hence (lemma, §5) every trace satisfies NE. Proof architecture: rely–guarantee over component contracts; stability of each contract under steps of other contract-satisfying components; preservation of the alias-freedom invariant. **Corollaries:** attenuation soundness (spatial axis) and revocation effectiveness (temporal axis, §6).

## 9. Scoping decision

Escalation means effects outside effective bounds, not information escaping through permitted effects. A narrowed sub-agent signalling secrets to a colluder via timing or choice among allowed effects is a noninterference-style hyperproperty and inherits McCullough's non-composability obstacle; paper one states this scope, cites McCullough as the reason, and defers the information-flow variant.

## 10. Known weaknesses and open questions

1. **"Currently processing" needs a semantics.** Contexts assume each effect is performed while servicing at most one request. Interleaved processing (a deputy multiplexing several requests) needs either per-activation contexts (continuations carry π) or a restriction to run-to-completion request handling in the core calculus. Candidate: run-to-completion for the core theorem; per-activation contexts as an extension. **Unresolved — resolve before Alloy encoding.**
2. **Q1 (structured E)** carried from v0.1; forced when the Lean transition system is written.
3. **Prior-art positioning** (unchanged obligation): check Maffeis–Mitchell–Taly 2010 (authority safety via reachability) and Sewell et al. 2011 (seL4 integrity) for analogues of attached bounds / chain attribution; claimed novelty lives in (a) open-system compositional formulation, (b) per-delegation bounds and contexts as first-class, (c) temporal axis (mid-trajectory revocation) integrated with (b), (d) agent-trajectory instantiation. Verify (a)–(d) against the papers, not summaries of them.
4. **Over-restriction check.** Dual accounting (own effects vs. request-context effects, via Honest tagging) is the answer to deputies doing legitimate internal work while servicing narrow requests; confirm in Alloy that a logging deputy satisfying its contract is not flagged.
5. **The attribution relation's inductive definition in Lean** — contexts threading through spawn (does a spawned sub-agent inherit the spawner's current π?) is undecided. Candidate: spawn-for-request inherits π extended with the spawner; spontaneous spawn starts ⟨⟩. **Resolve with 1.**

1. Benchmark 1 with performer-only attribution → reproduce invisibility (motivating counterexample #1).
2. Benchmark 1 with contexts + Guard → no counterexample at scope 5–6.
3. Benchmark 2 (shared service) without attached bounds → reproduce NE-S-holds-while-attack-succeeds (motivating counterexample #2); with NE-D → flagged; with attached bounds chosen correctly by P → no counterexample.
4. Benchmark 3 with a handoff caretaker → membrane violation + post-clear effect; with forwarding caretaker → revocation-effectiveness holds.
5. Benchmark 4 (laundering): trusted deputy violating Honest tagging → NE violation attributable to the contract breach; untrusted retention case → verify no NE violation *and* verify caretaker routing closes the temporal gap.
6. §10.4 over-restriction: contract-satisfying logging deputy → no false flag.
